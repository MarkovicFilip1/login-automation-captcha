While working on this project, I realized that CAPTCHA verification ("I'm not a robot") makes full login automation more challenging, as it is designed to prevent automated interactions.

In a real-world scenario, I would approach this differently by using a dedicated test environment where CAPTCHA is disabled or replaced with a test-friendly alternative. This would allow the login flow to be automated reliably while keeping CAPTCHA verification separate.

This project was a useful learning experience in understanding the limitations of UI automation and choosing the right approach for different testing scenarios. It also helped me recognize when an application requires human interaction, such as CAPTCHA verification, and when manual testing may be a more appropriate approach.
